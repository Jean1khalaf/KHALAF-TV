# KHALAF TV updates — 2026-10-29

## Changes
- The phone remote-control interface (`/remote`) now displays its UI labels, pairing flow, controls, status messages, timer, favorites, and history in English.
- The four Elahmad channel pages remain embedded inside the KHALAF TV player; no forced redirect to an external browser was added.
- Removed the restrictive `sandbox` attribute from the Elahmad iframe so the provider page can run with its usual embedded-player behavior. Existing autoplay/media/fullscreen permissions remain enabled.

## Test checklist
1. Run `npm install`, then `npm run dev` (or your normal deployment flow).
2. Open `/remote`; verify pairing screen and all tabs are in English.
3. Pair with the 8-digit code displayed on the TV.
4. Test channel selection, directional pad, play/pause, volume, mute, fullscreen, favorites, history, and sleep timer.
5. Open each Elahmad channel on the TV and verify that its player renders in the embedded KHALAF TV frame.

## Important note about Elahmad playback
Removing the iframe sandbox can resolve restrictions caused by the embedding context, but it cannot override a provider's own HTTP 403 response, anti-hotlink checks, or browser `Content-Security-Policy` / `X-Frame-Options` restrictions. If a channel still shows 403 inside KHALAF TV while its page works directly, the provider's page or nested stream is refusing that embedded request; reliable integrated playback then requires a provider-supported embed or an authorized direct stream URL. See MDN's documentation on [CSP frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors) and [X-Frame-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options).
